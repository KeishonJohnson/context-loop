# Reusable Codex project setup instruction

Use this instruction when you want Codex to prepare an existing project. Replace
the project path and identify its real build documents and Obsidian project index.
It can also be added to your own project guidance when you choose to adopt that
workflow. Context Loop does not edit global instructions or all your repositories.

> Prepare /absolute/path/to/project for Context Loop existing-project mode.
> Preserve its source layout, Git metadata, original instruction files, build
> documents, decisions, and Obsidian notes. First read all applicable AGENTS.md,
> AGENTS.override.md, and CLAUDE.md guidance. Inspect the current build roadmap,
> scope, approved decisions and constraints, status/handoff, and the relevant
> Obsidian project index. List the actual source paths and flag missing sources or
> contradictory direction. Do not invent a replacement build plan.
>
> Use Context Loop inspect and attach to add only its dedicated configuration and
> control folder. Map governing source roles and approved note roots explicitly.
> Define small tasks that quote exact documented requirements. Add independent
> behavioral and regression checks under Context Loop/checks/. Limit writable
> paths to the code needed for those tasks. Research notes support the established
> build; they do not authorize changing scope or strategy.
>
> Present the source map, requirement bindings, write paths and definition of done
> for owner review. Do not approve on the owner's behalf, change governing notes,
> or start the loop unless the owner has explicitly authorized those steps. If
> authorization is already present in this session, record the actual decision
> rather than asking again. When starting work, run through Context Loop so every
> cycle uses the approved context and records independent acceptance evidence.
